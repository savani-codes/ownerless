How it works

Two people, two agents, one room.

Each agent is a Claude Code session with its own instructions and its own permission settings. The people decide; the agents do the legwork.

  1. 01

    Report

    The on-call engineer mentions @investigator in the room. That's the whole alert.

    JARS · 1 message
  2. 02

    Investigate

    It reads Airflow, the error log, the warehouse, DataHub and lineage, then posts a report where every claim has a link. It spots the table with no owner and asks who should own it.

    investigator · read-only
  3. 03

    Approve

    The Data Platform lead takes ownership and approves the numbered plan in plain words. An agent's message never counts as approval.

    SAV · 1 message
  4. 04

    Fix and log

    @operator assigns the owner, restores the data and reruns the pipeline. Each step stops at a permission prompt. Then it verifies and writes the incident log.

    operator · 3 Allow clicks

Safety

Every change needs two keys.

Key one

The owner approves

A person who owns the dataset approves the numbered steps in the thread. The operator acts on nothing else.

Key two

A person allows each command

Writes are never allowlisted, so Claude Code asks, and Switch shows Allow / Decline in the room. CI fails if a write ever slips into an allowlist.

Built on Switch

The room is the product.

There's no web app. Switch brings the agents into the chat where the team already works, and keeps them in check.

Room template

One form creates both agents, the room, its rules, a group directory and a kickoff.

Two agents, one room

Separate Claude Code sessions, each in its own folder with its own role and permissions.

@mentions and threads

People start agents, agents hand off to each other, and the whole incident lives in one thread.

Permission prompts

Every write waits for Allow or Decline from a person, right in the chat.

Room instructions

The workflow and the two-key rule, read by every agent that joins.

Room documents

A group directory goes in. The incident log comes out.

Architecture

One tool, four systems.

The agents have exactly one tool: the ownerless CLI. It prints JSON with a link for every entity. Reads run freely; writes stop for a person.

Run it

From a clean clone to a broken pipeline.

Windows with Git Bash, macOS or Linux. You need Docker, uv, the DataHub CLI and Switch Console with Claude Code. Then create the room from switch/ownerless.template.yaml.

Full instructions → 
# the stack
git clone --recurse-submodules \
  https://github.com/savani-codes/ownerless.git
cd ownerless
datahub docker quickstart
scripts/setup.sh
scripts/up.sh --seed
scripts/preflight.sh

# the incident
ownerless scenario reset
ownerless scenario break
ownerless scenario trigger

# then, in the room
@investigator daily_revenue didn't refresh, what happened?

The next incident starts with a name.
